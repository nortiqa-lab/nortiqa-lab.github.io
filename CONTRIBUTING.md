# Contributing

## Flujo
1. Trabajar en una rama dedicada.
2. Abrir PR contra `main`.
3. Completar la plantilla de PR.
4. Esperar checks verdes.
5. Obtener revisión requerida.
6. Mergear sólo cuando el cambio cumpla gobernanza.

## Reglas mínimas
- No push directo a `main` cuando el enforcement esté activo.
- No secretos ni datos reales en Git.
- No mezclar entidades.
- No editar runtime/PROD desde un PR documental.
- Cambios estructurales permanecen DEV hasta auditoría y ratificación.
- Commits deben describir intención y alcance.

## Código generado por IA
Todo código generado o modificado por IA debe ser revisado, testeado y tratado como código no confiable hasta pasar validaciones.

## Dependencias
Dependencias nuevas deben justificarse y revisar licencia, mantenimiento y superficie de riesgo.
